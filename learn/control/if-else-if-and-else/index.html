if, else if and else

Programs make decisions. if runs a block of code only when a condition is true, and else gives the alternative:

fn main() {
    let temperature = 31;
    if temperature > 30 {
        println!("Hot: stay in the shade");
    } else if temperature > 15 {
        println!("Pleasant");
    } else {
        println!("Bring a jacket");
    }
    println!("Forecast done");
}

Hot: stay in the shade
Forecast done
  • The condition (temperature > 30) comes right after if, without parentheses. The braces are required, even around a single line.
  • Rust checks the conditions from top to bottom and runs only the first block whose condition is true. Here 31 > 30, so "Hot" runs and the else if is never checked, even though 31 > 15 is also true.
  • else if adds another condition; you can have as many as you need.
  • else (optional) runs when none of the conditions were true.

Comparison operators

You met these in the Types module; now they drive decisions:

Operator Meaning
== equal
!= not equal
< and > less than, greater than
<= and >= less or equal, greater or equal

Combine conditions with && (and), || (or) and ! (not): if age >= 18 && has_ticket { ... }.

Conditions must be bools

fn main() {
    let lives = 3;
    if lives {
        println!("still alive");
    }
}

error[E0308]: mismatched types
 --> src/main.rs:3:8
  |
3 |     if lives {
  |        ^^^^^ expected `bool`, found integer

Unlike C, JavaScript or Python, Rust doesn't treat numbers as true or false. Write the comparison you mean: if lives > 0.

Order matters

Because the first true condition wins, put the most specific check first. This version is wrong: a score of 95 prints "pass", because score >= 50 is checked first and the second branch is never reached:

if score >= 50 {
    println!("pass");
} else if score >= 90 {
    println!("excellent");
}

Swap the two conditions and it works.

Common mistakes

  • = instead of ==: if score = 100 is an assignment, not a comparison, so it's error[E0308]: mismatched types (expected bool, found ()).
  • Parentheses out of habit: if (x > 5) works, but rustc warns unnecessary parentheses around `if` condition. Leave them out.
  • Comparing different types: if count > 2.5 with an integer count doesn't compile; Rust never converts number types for you.
