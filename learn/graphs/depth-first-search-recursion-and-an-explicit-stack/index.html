Depth-first search: recursion and an explicit stack

Depth-first search (DFS) goes as deep as it can along one path, and only when it gets stuck does it back up and try the next branch. It's the natural way to ask "what can I reach from here?", to count separate groups (connected components), to detect cycles, to flood-fill a region of a map, and it's the basis of topological sorting.

Recursion expresses it directly: visit a node, then recursively visit each unvisited neighbor.

fn explore(u: usize, adj: &[Vec<usize>], seen: &mut [bool], members: &mut Vec<usize>) {
    seen[u] = true;
    members.push(u);
    for &v in &adj[u] {
        if !seen[v] {
            explore(v, adj, seen, members);
        }
    }
}

fn main() {
    // friendships: 0-1, 1-2, 3-4, and 5 knows nobody
    let adj = vec![vec![1], vec![0, 2], vec![1], vec![4], vec![3], vec![]];
    let mut seen = vec![false; adj.len()];
    for start in 0..adj.len() {
        if !seen[start] {
            let mut members = Vec::new();
            explore(start, &adj, &mut seen, &mut members);
            println!("group: {members:?}");
        }
    }
}

group: [0, 1, 2]
group: [3, 4]
group: [5]

The outer loop starts a new DFS from every node not seen yet; each DFS marks one whole component. Every node and edge is handled once: O(V + E).

The same thing with a stack

Recursion depth equals the length of the path DFS is following. On a long chain or a big grid that can be hundreds of thousands of calls deep, and the program dies with thread 'main' (4242) has overflowed its stack. The fix is to keep your own stack in a Vec, which lives on the heap and can grow as needed:

fn reachable(adj: &[Vec<usize>], start: usize) -> Vec<usize> {
    let mut seen = vec![false; adj.len()];
    let mut stack = vec![start];
    let mut order = Vec::new();
    while let Some(u) = stack.pop() {
        if seen[u] {
            continue; // pushed twice before we got to it
        }
        seen[u] = true;
        order.push(u);
        for &v in adj[u].iter().rev() {
            if !seen[v] {
                stack.push(v);
            }
        }
    }
    order
}

fn main() {
    let adj = vec![vec![1, 3], vec![2], vec![], vec![4], vec![]];
    println!("{:?}", reachable(&adj, 0));
}

[0, 1, 2, 3, 4]

Pushing the neighbors in reverse makes the stack pop them in their original order, so the visiting order matches the recursive version. Here a node can sit on the stack more than once, so it's checked when popped (continue if already seen).

Common mistakes

  • Forgetting the visited check in a graph with cycles: the search goes around forever.
  • Recursive DFS on huge inputs. Fine for trees and small graphs; for a 1,000 by 1,000 grid, use an explicit stack.
  • Expecting shortest paths from DFS. DFS finds a path; BFS finds the shortest.
