Grouping data with a struct

So far, related values have lived in separate variables: name, score, level. With three players you'd juggle nine variables, and nothing stops you from mixing up whose score is whose. A tuple like (String, u32, u8) groups them, but player.1 doesn't say what the number means.

A struct (short for structure) is a type you define yourself that groups related values under one name. Each value is a field, with a name and a type.

struct Player {
    name: String,
    score: u32,
    level: u8,
}

fn main() {
    let p = Player {
        name: String::from("Ferris"),
        score: 1200,
        level: 7,
    };
    println!("{} is level {} with {} points", p.name, p.level, p.score);
}

Ferris is level 7 with 1200 points

Piece by piece:

  • struct Player { ... } defines a new type called Player. It goes outside fn main, at the top level of the file. A definition is a blueprint: it doesn't create any value by itself.
  • Inside the braces, each field is written name: Type, separated by commas. A comma after the last field is normal Rust style (cargo fmt adds it for you).
  • Player { name: ..., score: ..., level: ... } creates an instance: an actual value of type Player. You must give every field a value, but the order doesn't have to match the definition.
  • p.name reads a field with a dot, the same way you read .0 of a tuple, but with a name that says what it is.

Type names use UpperCamelCase (Player, InventoryItem); field names use snake_case, like variables. The compiler warns you if you mix them up.

Why bother?

A struct gives meaning to data. p.score says what the number is, the type Player can appear in function signatures (fn print_player(p: &Player)), and the compiler guarantees that every Player has all of its fields. Fields can be any type: numbers, bool, String, arrays, tuples, even other structs.

For text fields, use String: the struct then owns its text, just like a String variable does. A &str field would borrow text owned by someone else, which needs lifetimes, a later module. Owned fields are the right default.

Common mistakes

  • Leaving out a field. Every field needs a value; there are no automatic defaults:
struct Player {
    name: String,
    score: u32,
}

fn main() {
    let p = Player { name: String::from("Ferris") };
    println!("{}", p.name);
}

error[E0063]: missing field `score` in initializer of `Player`
  • = instead of : when creating an instance: Player { name = ... } gives expected `:`, found `=` . Fields use colons both in the definition and in the instance.
  • A semicolon after the definition: struct Player { ... }; gives expected item, found `;` . A struct definition with braces ends with } alone.
