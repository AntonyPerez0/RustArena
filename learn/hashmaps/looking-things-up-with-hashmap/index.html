Looking things up with HashMap

A HashMap<K, V> stores key-value pairs: you file a value under a key, then ask for the value by its key. A price list (item to price), a phone book (name to number), an inventory (product to quantity). To find "kiwi" in a vector you'd check every element; a HashMap computes a number from the key, its hash, and uses it to jump almost straight to the right slot. A lookup takes about the same time with ten entries or ten million.

use std::collections::HashMap;

fn main() {
    let mut stock: HashMap<String, u32> = HashMap::new();
    stock.insert(String::from("apple"), 12);
    stock.insert(String::from("pear"), 0);
    stock.insert(String::from("kiwi"), 7);

    println!("{} kinds", stock.len());
    println!("apples: {:?}", stock.get("apple"));
    println!("mangos: {:?}", stock.get("mango"));
    println!("kiwi listed? {}", stock.contains_key("kiwi"));

    let old = stock.insert(String::from("apple"), 20);
    println!("apples were {:?}, now {:?}", old, stock.get("apple"));

    let removed = stock.remove("pear");
    println!("removed {:?}, {} kinds left", removed, stock.len());
}

3 kinds
apples: Some(12)
mangos: None
kiwi listed? true
apples were Some(12), now Some(20)
removed Some(0), 2 kinds left

Piece by piece:

  • use std::collections::HashMap; HashMap isn't in the prelude (the short list of names every Rust file gets automatically), so you import it.
  • HashMap<String, u32>: every key is a String, every value a u32.
  • insert(key, value) adds a pair. Keys are unique: inserting an existing key replaces its value and returns the old one as Some(old) (or None for a new key).
  • get(key) returns Option<&V>, because the key might not be there. A map with String keys can be searched with a plain &str like "apple": you don't have to build a String just to look something up.
  • contains_key answers yes or no, len counts the pairs, and remove takes a pair out and returns its value as an Option.

Getting values out and changing them

get hands you a reference inside an Option. To get a plain number, with a default for missing keys, match on it; the pattern Some(&n) matches the reference and copies the number out of it (the same & trick as retain(|&r| ...) in the vectors module):

use std::collections::HashMap;

fn main() {
    let mut stock: HashMap<&str, u32> = HashMap::new();
    stock.insert("kiwi", 7);

    let mangos = match stock.get("mango") {
        Some(&n) => n,
        None => 0,
    };
    println!("mangos: {mangos}");

    if let Some(qty) = stock.get_mut("kiwi") {
        *qty -= 1;
    }
    println!("kiwis: {}", stock["kiwi"]);
}

mangos: 0
kiwis: 6
  • The one-liner stock.get("mango").copied().unwrap_or(0) does the same as that match; module 19 covers unwrap_or and friends.
  • get_mut returns Option<&mut V>, a mutable reference you can write through with *.
  • stock["kiwi"] reads a value directly, but panics if the key is missing. Use it only when you know the key is there.
  • This map uses &str keys. That's fine when the keys are string literals or text that outlives the map; for text you read at run time, use String keys.

insert takes ownership of the key and the value: after stock.insert(name, 3) with a String name, the map owns it and name can't be used any more.

Common mistakes

  • Assigning through an index:

    use std::collections::HashMap;

fn main() {
    let mut stock: HashMap<&str, i32> = HashMap::new();
    stock.insert("apple", 3);
    stock["apple"] = 5;
}

    error[E0594]: cannot assign to data in an index of `HashMap<&str, i32>`

    Use insert("apple", 5) to replace, or get_mut to change the value in place.

  • Printing the whole map with {:?}. It compiles, but the order of the pairs changes from run to run. The next step explains why and what to do instead.
