'static: references that live forever

One lifetime name is built in: 'static, meaning "valid for the entire run of the program". Every string literal is a &'static str. Its bytes are stored inside the compiled program itself, so they're never freed.

fn level_name(code: u8) -> &'static str {
    match code {
        0 => "debug",
        1 => "info",
        2 => "warn",
        _ => "error",
    }
}

const APP: &str = "RustArena";

fn main() {
    let name;
    {
        let code = 2;
        name = level_name(code);
    }
    println!("{APP}: {name}");
}

RustArena: warn
  • level_name takes no references, so elision has nothing to borrow from: -> &str alone would be E0106. The result is always a literal, so &'static str is the honest answer, and the caller can keep it as long as it likes.
  • Constants and statics are always 'static, so const APP: &str doesn't need the annotation.
  • A struct field can also be &'static str with no lifetime parameter on the struct: struct HttpError { code: u16, reason: &'static str }. That's common for fixed messages and lookup tables.

Common mistakes

  • Adding 'static to make an error go away. When the compiler complains about lifetimes, it's tempting. It never works for data created while the program runs, because that data really is dropped:
fn make_label(id: u32) -> &'static str {
    let s = format!("ticket-{id}");
    &s
}

fn main() {
    println!("{}", make_label(7));
}

error[E0515]: cannot return reference to local variable `s`

s is a String built at run time and dropped at the end of make_label. The real fix, returning a String, is the next step. Read the help on E0106 carefully too: it suggests 'static, but adds "this is uncommon unless you're returning a borrowed value from a const or a static".

  • Reading T: 'static as "lives forever". You'll meet 'static as a bound on a type, for example in std::thread::spawn. T: 'static means "contains no borrowed references that could expire". Every owned type qualifies: String, Vec<u32>, i32, your structs without references. The threads module explains why spawn needs it.
