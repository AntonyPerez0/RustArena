Sorting and custom orderings

You've used sort since the vectors module. Here's what's behind it, and how to sort by anything.

  • v.sort() is stable: items that compare equal keep their original order. It's O(n log n) and uses some extra memory.
  • v.sort_unstable() may reorder equal items, but it's usually faster and needs no extra memory. For plain numbers, where equal items are indistinguishable, it's the idiomatic choice (clippy's pedantic stable_sort_primitive lint suggests it).
  • Both need T: Ord. For anything else, say how to compare:
Method Use it when
sort_by_key(|x| key) one key, cheap to compute (a number, a Copy field)
sort_by_key(|x| Reverse(key)) the same, high to low
sort_by(|a, b| a.f.cmp(&b.f)) keys you'd have to clone, or several keys
sort_by_cached_key(|x| key) an expensive key (computed once per item)

Several keys

cmp returns an Ordering (Less, Equal or Greater). ordering.then(other) uses other only when the first comparison was Equal, which is exactly how "sort by department, then by salary" works. then_with(|| ...) does the same but only computes the second comparison when needed. To flip one key, swap a and b (or call .reverse() on that Ordering).

use std::cmp::Reverse;

struct Employee {
    name: &'static str,
    dept: &'static str,
    salary: u32,
}

fn main() {
    let mut staff = vec![
        Employee { name: "Mo", dept: "ops", salary: 61_000 },
        Employee { name: "Ana", dept: "dev", salary: 82_000 },
        Employee { name: "Bo", dept: "dev", salary: 95_000 },
        Employee { name: "Cy", dept: "ops", salary: 61_000 },
        Employee { name: "Di", dept: "dev", salary: 82_000 },
    ];
    // department A-Z, then salary high to low, then name A-Z
    staff.sort_by(|a, b| {
        a.dept
            .cmp(&b.dept)
            .then(b.salary.cmp(&a.salary))
            .then(a.name.cmp(&b.name))
    });
    for e in &staff {
        println!("{:<4} {:<4} {}", e.dept, e.name, e.salary);
    }

    staff.sort_by_key(|e| Reverse(e.salary));
    println!("top earner: {}", staff[0].name);

    let mut temps: Vec<f64> = vec![21.5, -3.0, 18.25, 0.0];
    temps.sort_by(|a, b| a.total_cmp(b));
    println!("{temps:?}");
}

  • Floats don't implement Ord (NaN isn't comparable), so sort won't compile on a Vec<f64>. f64::total_cmp is a full ordering for floats, made for exactly this. (The : Vec<f64> annotation matters: total_cmp belongs to a specific float type, and a bare 21.5 could still be an f32.)
  • When a type has one obvious order (a version number, a date), implement Ord for it (module 23) and plain sort() works. When the order depends on the screen or report, use sort_by.
  • Related tools: v.is_sorted(), iter.max_by_key(...), iter.min_by(|a, b| a.total_cmp(b)).

Common mistakes

  • Sorting floats with sort():
fn main() {
    let mut v = vec![3.2, 1.5, 2.0];
    v.sort();
    println!("{:?}", v);
}

error[E0277]: the trait bound `{float}: Ord` is not satisfied
  • sort_by_key with a String field. The key closure must return the key by value, and it can't move the String out of the borrowed item:
struct Player {
    name: String,
    score: u32,
}

fn main() {
    let mut players = vec![Player { name: String::from("Zed"), score: 3 }];
    players.sort_by_key(|p| p.name);
    println!("{}", players[0].score);
}

error[E0507]: cannot move out of `p.name` which is behind a shared reference

Use sort_by(|a, b| a.name.cmp(&b.name)) (no copy) rather than sort_by_key(|p| p.name.clone()) (a new String for every comparison).

  • Descending with a minus sign. sort_by_key(|x| -x) doesn't work for unsigned types and overflows for i32::MIN. Use Reverse(x).
  • No tie-breaker. If two items can compare equal, decide what happens; otherwise the output order depends on the input order, and tests break when the input changes.
