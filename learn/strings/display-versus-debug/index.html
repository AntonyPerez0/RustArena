Display versus Debug

{} and {:?} call two different formatting abilities (traits):

  • Display ({}) is the text for users: clean, no quotes, decided by the type's author.
  • Debug ({:?}) is the text for programmers: unambiguous, showing quotes, escapes and structure. {:#?} is the pretty, multi-line version.
fn main() {
    let name = "Ferris \"the crab\"";
    println!("{}", name);
    println!("{:?}", name);
    println!("{:?}", "a\tb");
    println!("{} vs {:?}", 'x', 'x');
    println!("{:?} {:?}", Some("ok"), vec!["a", "b"]);
}

Ferris "the crab"
"Ferris \"the crab\""
"a\tb"
x vs 'x'
Some("ok") ["a", "b"]

Debug output is what you want in logs and test failures: with {:?} you can see a stray tab or trailing space that {} would hide.

Collections and Option only have Debug. There's no single "right" way to show a list to a user, so Rust leaves it to you:

fn main() {
    println!("{}", vec![1, 2]);
}

error[E0277]: `Vec<{integer}>` doesn't implement `std::fmt::Display`

Display for your own types

#[derive(Debug)] writes Debug for you (module 12). Display you write yourself, because only you know how your type should look to users. The shape is always the same:

use std::fmt;

struct Money {
    cents: i64,
}

impl fmt::Display for Money {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let sign = if self.cents < 0 { "-" } else { "" };
        let abs = self.cents.abs();
        write!(f, "{}${}.{:02}", sign, abs / 100, abs % 100)
    }
}

fn main() {
    let price = Money { cents: 1999 };
    let refund = Money { cents: -250 };
    println!("{price} and {refund}");
    let text = price.to_string();
    println!("{} chars: {text}", text.len());
}

$19.99 and -$2.50
6 chars: $19.99
  • impl fmt::Display for Money says "here's how Money does Display". It has one method, fmt, which you copy in this exact shape. (Formatter<'_> contains a lifetime placeholder; module 24 explains it, and you can copy it as is.)
  • write!(f, ...) works like format!, but writes into the formatter f. Its result, a fmt::Result, is what fmt returns.
  • Once a type has Display, {} works for it everywhere (println!, format!, panic!), and you get .to_string() for free.
  • Need several write! calls? Each returns a fmt::Result, and real code ends them with ? to stop on an error (module 19). Until then, build the text in a String and write! it once.

Common mistake: width on your own type

A width like {:>10} is handled by each type's fmt, and a fmt that just calls write! ignores it:

use std::fmt;

struct Money {
    cents: i64,
}

impl fmt::Display for Money {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "${}.{:02}", self.cents / 100, self.cents % 100)
    }
}

fn main() {
    let m = Money { cents: 1999 };
    println!("[{:>10}]", m);
    println!("[{:>10}]", m.to_string());
}

[$19.99]
[    $19.99]

Format it into a String first (as above), or make your fmt end with f.pad(&text), which applies the caller's width and alignment.
