Parameters

A function becomes much more useful when you can hand it values to work with. These inputs are parameters, declared inside the parentheses, each with a name and a type:

fn main() {
    greet("Ferris");
    greet("Corro");
    show_score("Ferris", 120);
}

fn greet(name: &str) {
    println!("Hello, {name}!");
}

fn show_score(player: &str, points: i32) {
    println!("{player}: {points} points");
}

Hello, Ferris!
Hello, Corro!
Ferris: 120 points
  • name: &str declares a parameter called name of type &str (text, like a string literal).
  • The values you pass in a call, like "Ferris", are the arguments. Each argument becomes the value of its parameter for that one call: name is "Ferris" in the first call and "Corro" in the second.
  • Several parameters are separated by commas, and the arguments are matched to them in order.
  • Parameters are variables that belong to the function: immutable by default, and gone when the function ends.

Parameter types are required

Inside a function, Rust infers the types of variables. A function's parameters, though, always need written types. The first line of a function, its signature, is a contract: callers can see exactly what to pass without reading the body, and the compiler checks every call against it. When a call is wrong, the error points at that call, not somewhere deep inside the function.

fn greet(name) {
    println!("Hello, {name}!");
}

fn main() {
    greet("Ferris");
}

Common mistakes

The number of arguments must match the number of parameters:

fn show_score(player: &str, points: i32) {
    println!("{player}: {points} points");
}

fn main() {
    show_score("Ferris");
}

error[E0061]: this function takes 2 arguments but 1 argument was supplied
 --> src/main.rs:6:5
  |
6 |     show_score("Ferris");
  |     ^^^^^^^^^^---------- argument #2 of type `i32` is missing
  • Wrong type: show_score("Ferris", "120") is error[E0308]: mismatched types (expected i32, found &str). Quotes make "120" text, not a number.
  • Swapped arguments: show_score(120, "Ferris") doesn't compile either, because the types don't line up. But when two parameters have the same type, like fn rectangle(width: u32, height: u32), swapping them compiles and quietly gives wrong results. Clear parameter names are your defense.
