Dynamic JSON with Value and json!

Sometimes you don't want a struct: you only need one field from a big document, the shape varies, or you're building a quick response. For that, serde_json has serde_json::Value, an enum that can hold any JSON:

enum Value {
    Null,
    Bool(bool),
    Number(Number),
    String(String),
    Array(Vec<Value>),
    Object(Map<String, Value>),
}

use serde_json::{json, Value};

fn main() {
    let text = r#"{"user": {"name": "Ferris", "tags": ["crab", "admin"]}, "visits": 12}"#;
    let v: Value = serde_json::from_str(text).unwrap();

    println!("{}", v["user"]["name"]);
    println!("{:?}", v["user"]["name"].as_str());
    println!("{}", v["visits"].as_u64().unwrap_or(0) + 1);
    println!("{}", v["user"]["email"]);
    println!("{}", v["user"]["tags"][1]);

    let reply = json!({ "ok": true, "visits": v["visits"], "id": 7 });
    println!("{reply}");
}

Some("Ferris")
13
null
"admin"
{"id":7,"ok":true,"visits":12}

Piece by piece:

  • v["user"]["name"] indexes into objects by key and arrays by position. A missing key or index gives Value::Null instead of panicking, so you can chain lookups safely.
  • Printing a Value prints JSON: a string comes out with its quotes, "Ferris". To get the Rust text, use the accessors: as_str(), as_u64(), as_i64(), as_f64(), as_bool(), as_array(), as_object(). Each returns an Option: None if the value is missing or of another type.
  • v.get("user") is the Option-returning lookup: None when the key isn't there.
  • The json! macro builds a Value with JSON syntax, and you can put Rust expressions inside (v["visits"] here, or any variable that implements Serialize).
  • Object keys come out sorted (id, ok, visits): serde_json's Map is a BTreeMap unless you enable its preserve_order feature. Sorted is deterministic, which tests like.

Value is an ordinary enum, so you can match on it:

use serde_json::Value;

fn describe(v: &Value) -> String {
    match v {
        Value::Null => String::from("nothing"),
        Value::Bool(b) => format!("yes/no: {b}"),
        Value::Number(n) => format!("number {n}"),
        Value::String(s) => format!("text {s}"),
        Value::Array(items) => format!("list of {}", items.len()),
        Value::Object(map) => format!("object with {} keys", map.len()),
    }
}

fn main() {
    let v: Value = serde_json::from_str(r#"[null, true, 2.5, "hi", [1, 2], {"a": 1}]"#).unwrap();
    for item in v.as_array().unwrap() {
        println!("{}", describe(item));
    }
}

You can also convert between the two worlds: serde_json::to_value(&my_struct) and serde_json::from_value::<MyStruct>(value).

When to use which

Prefer structs: the compiler checks every field access, and a wrong shape is reported in one place, at parse time. Use Value for genuinely dynamic data (arbitrary user metadata, proxying JSON you don't own, picking one field out of a huge response) and for tests, where json! makes expected values easy to write.

Common mistakes

  • Printing v["name"] and getting quotes. Use v["name"].as_str().
  • unwrap() on accessors for data you don't control: v["age"].as_u64().unwrap() panics if age is missing or "12" (a string). Use unwrap_or, if let, or ? on an Option.
  • Typos are silent. v["usr"]["name"] is just Null, no error. That's the price of skipping structs.
