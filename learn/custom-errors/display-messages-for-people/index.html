Display: messages for people

{:?} prints InsufficientFunds { balance: 70, requested: 500 }. That's useful in a log for developers, but a customer should see insufficient funds: balance 70, requested 500. The {} placeholder uses a different format, called Display, and for your own types you write it yourself (you did it for Money in module 18). Error types work the same way.

Display is a trait: a named set of methods that a type promises to have (module 22 covers traits properly). You make {} work for your type by implementing the Display trait for it. The recipe always has the same shape:

use std::fmt;

#[derive(Debug)]
enum WithdrawError {
    InvalidAmount,
    InsufficientFunds { balance: u64, requested: u64 },
    AccountFrozen,
}

impl fmt::Display for WithdrawError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            WithdrawError::InvalidAmount => write!(f, "amount must be greater than zero"),
            WithdrawError::InsufficientFunds { balance, requested } => {
                write!(f, "insufficient funds: balance {balance}, requested {requested}")
            }
            WithdrawError::AccountFrozen => write!(f, "account is frozen"),
        }
    }
}

fn main() {
    let errors = [
        WithdrawError::InvalidAmount,
        WithdrawError::InsufficientFunds { balance: 70, requested: 500 },
        WithdrawError::AccountFrozen,
    ];
    for e in &errors {
        println!("declined: {e}");
    }
    let message = errors[2].to_string();
    println!("{message:?} has {} characters", message.len());
    println!("{:?}", errors[0]);
}

declined: amount must be greater than zero
declined: insufficient funds: balance 70, requested 500
declined: account is frozen
"account is frozen" has 17 characters
InvalidAmount

Piece by piece:

  • use std::fmt; brings the formatting module into scope, so you can write fmt::Display instead of std::fmt::Display.
  • impl fmt::Display for WithdrawError { ... } reads "here's how a WithdrawError is displayed".
  • fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result is the one method Display requires. The signature is fixed by the trait: copy it exactly. (Module 18 and the standard docs write fmt::Formatter<'_>; the '_ is a lifetime placeholder, which module 24 explains. Both forms compile and mean the same thing.)
  • write!(f, ...) works like format!, but writes the text into the formatter f. It returns a fmt::Result, so it's the value of each match arm, and of the whole method.
  • Once Display exists, {}, format! and .to_string() all work. {:?} still uses the derived Debug.

Workplace note: the standard library's documentation for errors recommends short, lowercase messages without a trailing period, like its own invalid digit found in string. Messages often get embedded in longer ones (error: could not load config: invalid digit found in string), and that reads well only if each piece is a lowercase fragment.

Common mistakes

  • Printing with {} before implementing Display:
#[derive(Debug)]
enum WithdrawError {
    AccountFrozen,
}

fn main() {
    let e = WithdrawError::AccountFrozen;
    println!("declined: {e}");
}

error[E0277]: `WithdrawError` doesn't implement `std::fmt::Display`
  • A ; after write! in a match arm. The arm must return the fmt::Result. In an arm without braces the ; is a syntax error (`match` arm body without braces); inside braces, { write!(...); } returns () and you get mismatched types.
  • Using println! inside fmt. That prints to the screen right away instead of producing the text. Always write!(f, ...).
  • Forgetting use std::fmt; gives cannot find module or crate `fmt` . Either add the use or write the full path std::fmt::Display.
