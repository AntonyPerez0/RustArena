Generic functions

Say you need the last element of a list of scores, then of a list of names, then of a list of prices. Without generics you'd write three functions with identical bodies:

fn last_i32(items: &[i32]) -> Option<&i32> { ... }
fn last_str(items: &[&str]) -> Option<&&str> { ... }
fn last_f64(items: &[f64]) -> Option<&f64> { ... }

Generics let you write it once, with a placeholder for the type:

fn last<T>(items: &[T]) -> Option<&T> {
    if items.is_empty() {
        None
    } else {
        Some(&items[items.len() - 1])
    }
}

fn swap<A, B>(pair: (A, B)) -> (B, A) {
    (pair.1, pair.0)
}

fn main() {
    let scores = [88, 92, 75];
    let names = vec!["ana", "bo"];
    let empty: [f64; 0] = [];
    println!("{:?}", last(&scores));
    println!("{:?}", last(&names));
    println!("{:?}", last(&empty));
    println!("{:?}", swap(("crab", 8)));
}

Some(75)
Some("bo")
None
(8, "crab")

Piece by piece:

  • <T> right after the function name declares a type parameter called T. Inside the function, T is used like any type: &[T] is "a slice of T", Option<&T> "maybe a reference to a T".
  • At each call, the compiler works out what T is from the arguments: i32 for scores, &str for names, f64 for empty. You don't write it.
  • A function can have several type parameters, separated by commas. In swap<A, B>, the two halves of the pair can be different types.
  • last works for any T because it never does anything with the values except hand out references. It doesn't compare them, add them or print them. The next step shows what happens when you need to.

You've been using generic code all along: Vec<T>, Option<T>, Result<T, E> and HashMap<K, V> are generic types, and slice methods like .last() and .first() are generic functions.

Naming: type parameters are usually single capital letters: T for "type", U for a second one, K/V for keys and values, E for errors. A descriptive name like Item is fine when it reads better.

Common mistakes

  • Forgetting to declare the parameter. Using T without <T> after the function name:
fn last(items: &[T]) -> Option<&T> {
    items.last()
}

fn main() {
    println!("{:?}", last(&[1, 2]));
}

error[E0425]: cannot find type `T` in this scope
  | fn last(items: &[T]) -> Option<&T> {
  |                  ^ not found in this scope
  help: you might be missing a type parameter
  • One parameter for two different types. In fn pair<T>(a: T, b: T), both arguments are the same T, so pair(1, "two") is mismatched types: expected integer, found &str. If they may differ, use two parameters: fn pair<A, B>(a: A, b: B).
  • Writing a generic function too early. Generic code is a little harder to read. If you only ever call a function with i32, write it for i32. Make it generic when a second real use shows up.
