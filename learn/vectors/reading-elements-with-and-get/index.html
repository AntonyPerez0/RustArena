Reading elements with [] and get

There are two ways to read an element. Indexing, v[i], gives you the element directly and panics if i is past the end. v.get(i) returns an Option: Some(&element) or None.

fn main() {
    let podium = vec!["Ferris", "Corro", "Bunny"];
    println!("winner: {}", podium[0]);
    println!("third: {}", podium[2]);

    match podium.get(5) {
        Some(name) => println!("sixth: {name}"),
        None => println!("no sixth place"),
    }
    println!("{:?} {:?}", podium.first(), podium.last());
}

winner: Ferris
third: Bunny
no sixth place
Some("Ferris") Some("Bunny")

Indexes start at 0, so the last valid index is len() - 1. first() and last() are get(0) and get(len - 1) with names, and return None on an empty vector.

Here's what happens when indexing goes past the end:

fn main() {
    let podium = vec!["Ferris", "Corro", "Bunny"];
    println!("checking place 4");
    println!("{}", podium[3]);
}

checking place 4

The program stops with this message, plus the file and line of the bad index:

index out of bounds: the len is 3 but the index is 3

A panic stops the program with a message. Unlike C or C++, Rust never reads whatever memory happens to be past the end: it always checks.

Which one to use

  • Use v[i] when an index past the end would be a bug in your own code (a loop bound you control). The panic points straight at the bug.
  • Use v.get(i) when the index comes from outside: user input, a file, a request. A missing element is then a normal situation you handle with match, if let or let ... else.

Indexes are usize

Indexes and lengths have the type usize. An i32 index doesn't compile:

fn main() {
    let v = vec![10, 20, 30];
    let i: i32 = 1;
    println!("{}", v[i]);
}

error[E0277]: the type `[{integer}]` cannot be indexed by `i32`

Make the variable a usize, or convert with i as usize when you know it isn't negative.

Common mistake: moving out by index

v[0] on a Vec<i32> copies the number. On a Vec<String> it would have to move the String out and leave a hole, which Rust doesn't allow:

fn main() {
    let names = vec![String::from("Ana"), String::from("Bo")];
    let first = names[0];
    println!("{first}");
}

error[E0507]: cannot move out of index of `Vec<String>`

Borrow it (let first = &names[0];) or copy it explicitly (names[0].clone()). In the same way, get gives you a reference (Option<&String>), never the value itself.
