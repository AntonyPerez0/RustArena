Reading every line until the end

Often you don't know how many lines are coming: a log file, a list of orders, a CSV export. Then you read until the input ends. When the input comes from a file, that's the end of the file (often called EOF). When you type into a terminal, you signal the end with Ctrl+D (Linux and macOS) or Ctrl+Z then Enter (Windows).

use std::io;

fn main() {
    let mut count = 0;
    for line in io::stdin().lines() {
        let line = line.expect("failed to read a line");
        count += 1;
        println!("{count}: {line}");
    }
    println!("{count} lines");
}

  • io::stdin().lines() hands out the input one line at a time, as Strings without the newline.
  • Each line comes wrapped in a Result, because reading can fail. let line = line.expect(...) unwraps it (shadowing again).
  • The loop ends by itself when the input runs out.

The classic form: lock() and BufRead

In existing code and older answers online you'll see this form. It does the same thing:

use std::io::{self, BufRead};

fn main() {
    let mut total = 0;
    for line in io::stdin().lock().lines() {
        let line = line.expect("failed to read a line");
        let n: i32 = line.trim().parse().expect("not a number");
        total += n;
    }
    println!("total: {total}");
}

  • use std::io::{self, BufRead}; imports io itself (self) and BufRead, a trait: a named set of methods that several types share (module 22). lines() on a locked stdin comes from BufRead, and a trait's methods can only be called when the trait is imported. Without the import, you get error E0599: no method named `lines` found for struct `StdinLock<'a>` , with a help line suggesting use std::io::BufRead;.
  • .lock() takes hold of stdin once for the whole loop instead of on every read, which is faster for big inputs. io::stdin().lines(), added in Rust 1.62, does that for you.

Skipping blank lines

Real input often has empty lines (a trailing blank line at the end of a file is very common). Skip them with continue:

use std::io;

fn main() {
    let mut names = 0;
    for line in io::stdin().lines() {
        let line = line.expect("failed to read a line");
        if line.trim().is_empty() {
            continue;
        }
        names += 1;
        println!("{names}. {}", line.trim());
    }
}

With read_line

read_line also tells you when the input has ended: it returns the number of bytes it read, and 0 means there was nothing left.

use std::io;

fn main() {
    let mut line = String::new();
    let mut longest = 0;
    loop {
        line.clear();
        let bytes = io::stdin().read_line(&mut line).expect("failed to read a line");
        if bytes == 0 {
            break;
        }
        let length = line.trim().chars().count();
        if length > longest {
            longest = length;
        }
    }
    println!("longest line: {longest} characters");
}

Common mistakes

  • Using the line before unwrapping it. line.trim() straight on the loop variable gives E0599, no method named `trim` found for enum `Result<T, E>` : unwrap it first with .expect(...).
  • Forgetting the BufRead import with lock().lines() (see above).
  • The program "hangs" in a terminal. It's waiting for more input: the loop only ends at the end of input, so press Ctrl+D (or Ctrl+Z, Enter on Windows).
