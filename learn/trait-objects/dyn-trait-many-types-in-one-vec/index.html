dyn Trait: many types in one Vec

Generics are great when a function works with one type at a time. But a drawing app needs one list holding circles, rectangles and triangles together, and a Vec<T> has a single element type:

trait Shape {
    fn area(&self) -> f64;
}

struct Circle {
    radius: f64,
}

struct Square {
    side: f64,
}

impl Shape for Circle {
    fn area(&self) -> f64 {
        3.0 * self.radius * self.radius
    }
}

impl Shape for Square {
    fn area(&self) -> f64 {
        self.side * self.side
    }
}

fn main() {
    let shapes = vec![Circle { radius: 1.0 }, Square { side: 2.0 }];
    println!("{}", shapes.len());
}

error[E0308]: mismatched types

The answer is a trait object: dyn Shape means "some value of a type that implements Shape; which type exactly is only known at run time". Because those types have different sizes, a trait object always sits behind a pointer, most often a Box:

use std::f64::consts::PI;

trait Shape {
    fn name(&self) -> String;
    fn area(&self) -> f64;
}

struct Circle {
    radius: f64,
}

struct Rect {
    w: f64,
    h: f64,
}

impl Shape for Circle {
    fn name(&self) -> String {
        String::from("circle")
    }
    fn area(&self) -> f64 {
        PI * self.radius * self.radius
    }
}

impl Shape for Rect {
    fn name(&self) -> String {
        String::from("rect")
    }
    fn area(&self) -> f64 {
        self.w * self.h
    }
}

fn main() {
    let shapes: Vec<Box<dyn Shape>> = vec![
        Box::new(Circle { radius: 1.0 }),
        Box::new(Rect { w: 2.0, h: 3.0 }),
        Box::new(Circle { radius: 2.0 }),
    ];
    let mut total = 0.0;
    for s in &shapes {
        println!("{}: {:.2}", s.name(), s.area());
        total += s.area();
    }
    println!("total: {:.2}", total);
}

circle: 3.14
rect: 6.00
circle: 12.57
total: 21.71

Piece by piece:

  • Box::new(value) moves the value to the heap and gives you a Box, an owning pointer to it. (The smart pointers module covers Box in depth.) Every Box<dyn Shape> is the same size, whatever shape is inside, so they fit side by side in a Vec.
  • Vec<Box<dyn Shape>> is "a vector of boxes, each holding some Shape". The annotation is needed: it tells Rust to turn each Box<Circle> and Box<Rect> into a Box<dyn Shape>.
  • s.name() and s.area() call the right implementation for whatever is in each box, decided while the program runs. This is dynamic dispatch (step 3 shows how it works).

Through a dyn Shape you can call the trait's methods, and nothing else: the compiler no longer knows the concrete type.

Common mistakes

  • Forgetting dyn. Vec<Box<Shape>> gives error[E0782]: expected a type, found a trait. Since the 2021 edition, dyn is required.
  • No pointer. Vec<dyn Shape> gives error[E0277]: the size for values of type `dyn Shape` cannot be known at compilation time. Put it in a Box (or use &dyn Shape).
  • Calling a method that isn't in the trait. If Circle has its own fn radius(&self), then on a Box<dyn Shape> you get error[E0599]: no method named `radius` found for struct `Box<dyn Shape>` . Add the method to the trait if every shape needs it.
