Dyn compatibility (object safety)

Not every trait can be used as dyn Trait. To call methods through a vtable, the compiler must be able to build that table without knowing the concrete type. A trait that allows it is dyn compatible (older docs and blog posts call it object safe).

trait Shape {
    fn area(&self) -> f64;
    fn scaled(&self, k: f64) -> Self;
}

struct Circle {
    radius: f64,
}

impl Shape for Circle {
    fn area(&self) -> f64 {
        3.0 * self.radius * self.radius
    }
    fn scaled(&self, k: f64) -> Self {
        Circle { radius: self.radius * k }
    }
}

fn main() {
    let shapes: Vec<Box<dyn Shape>> = vec![Box::new(Circle { radius: 1.0 })];
    println!("{}", shapes.len());
}

error[E0038]: the trait `Shape` is not dyn compatible
  |
  |     fn scaled(&self, k: f64) -> Self;
  |                                 ^^^^ ...because method `scaled` references the `Self` type in its return type

Through a dyn Shape, what would scaled return? A Circle? A Square? Its size isn't known at compile time, so there's no way to call it. The main rules, each with the same reason behind it:

  • No Self in the return type (or in arguments other than the receiver): the concrete type is unknown. Clone is the famous example: fn clone(&self) -> Self.
  • No generic methods like fn log<T: Display>(&self, value: T): there would be one version per T, infinitely many, and a vtable can't hold them all.
  • No functions without self like fn new() -> Self: there's no value to find a vtable through.
  • The trait can't require Sized, so trait Shape: Clone is not dyn compatible either (Clone requires Sized).

The fixes

  1. Exclude a method from the vtable with where Self: Sized. It can still be called on concrete types, just not through dyn:
trait Shape {
    fn area(&self) -> f64;
    fn scaled(&self, k: f64) -> Self
    where
        Self: Sized;
}

struct Circle {
    radius: f64,
}

impl Shape for Circle {
    fn area(&self) -> f64 {
        3.0 * self.radius * self.radius
    }
    fn scaled(&self, k: f64) -> Self {
        Circle { radius: self.radius * k }
    }
}

fn main() {
    let big = Circle { radius: 1.0 }.scaled(2.0);
    let shapes: Vec<Box<dyn Shape>> = vec![Box::new(Circle { radius: 1.0 }), Box::new(big)];
    for s in &shapes {
        println!("{}", s.area());
    }
}

Calling s.scaled(2.0) on a Box<dyn Shape> would now give error: the `scaled` method cannot be invoked on a trait object.

  1. Replace a generic parameter with a trait object: fn log(&self, value: &dyn Display) instead of fn log<T: Display>(&self, value: T).
  2. Return a box instead of Self: to clone trait objects, add fn clone_box(&self) -> Box<dyn Shape> and implement it as Box::new(self.clone()).
  3. Split the trait: keep the dyn-friendly methods in one trait and put constructors or generic helpers in another.
