Deref and Drop: what makes a pointer smart

Two traits give smart pointers their behavior. Deref makes a type usable like a reference to what it holds. Drop runs cleanup code when a value goes away. You met both briefly in the std traits module; here's how they work together.

Deref and deref coercion

impl Deref for MyType { type Target = T; fn deref(&self) -> &T } says "a &MyType can be used as a &T". Then two things happen automatically:

  • *value works, and method calls look through the pointer: boxed_string.len() finds String::len.
  • Deref coercion: when you pass &MyType where a &T is expected, Rust inserts the deref calls for you, as many steps as needed.
use std::ops::Deref;

struct Username(String);

impl Deref for Username {
    type Target = String;

    fn deref(&self) -> &String {
        &self.0
    }
}

fn greet(name: &str) {
    println!("Welcome, {name}!");
}

fn main() {
    let user = Username(String::from("ferris"));
    println!("{} letters", user.len()); // String::len, through Deref
    greet(&user); // &Username -> &String -> &str

    let boxed = Box::new(String::from("corro"));
    greet(&boxed); // &Box<String> -> &String -> &str
}

Welcome, ferris!
Welcome, corro!

Box<T> implements Deref<Target = T>, String implements Deref<Target = str>, and Vec<T> implements Deref<Target = [T]>. That's why a &String works where a &str is wanted and a &Vec<T> where a &[T] is. Implement Deref for wrapper types that are a kind of pointer or container; the Rust API guidelines warn against using it to fake inheritance between unrelated structs.

Drop: cleanup at the end of a scope

When a value goes out of scope, Rust calls its drop method (if it has one), then drops its fields. That's how a Box frees its heap memory, a File closes, and a lock is released. This pattern of "cleanup tied to a value's lifetime" is called RAII. The order is fixed, so you can rely on it:

struct Noisy(&'static str);

impl Drop for Noisy {
    fn drop(&mut self) {
        println!("drop {}", self.0);
    }
}

fn main() {
    let _a = Noisy("a");
    let b = Noisy("b");
    {
        let _inner = Noisy("inner");
        println!("leaving inner scope");
    }
    drop(b); // drop right now
    let _c = Noisy("c");
    println!("end of main");
}

  • Values are dropped at the end of their scope, in reverse order of declaration: _c (declared last) goes before _a. Later values may depend on earlier ones, so they go first.
  • drop(b) drops a value early. It's an ordinary function from the prelude (std::mem::drop) that takes ownership and does nothing, so the value is dropped when the function ends.
  • The fields of a struct are dropped after the struct's own drop, in the order they're declared. Elements of a Vec are dropped first to last.

Common mistakes

  • Calling .drop() yourself: b.drop() is error[E0040]: explicit use of destructor method. Use drop(b); Rust must be sure it never runs twice.
  • let _ = Noisy("x"); drops the new value immediately. The pattern _ doesn't bind anything, so a guard created that way is gone on the same line. Write let _guard = ... to keep it alive until the end of the scope.
  • Using a value after drop(x): drop took ownership, so it's error[E0382]: borrow of moved value.
