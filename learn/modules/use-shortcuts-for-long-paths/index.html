use: shortcuts for long paths

Writing crate::restaurant::kitchen::cook over and over gets old. use creates a shortcut: a local name for a path, valid in the module where you write it.

mod shapes {
    pub mod circle {
        pub fn area(r: f64) -> f64 {
            std::f64::consts::PI * r * r
        }
    }

    pub mod square {
        pub fn area(side: f64) -> f64 {
            side * side
        }
    }
}

use shapes::circle;
use shapes::square::area as square_area;
use std::collections::{BTreeMap, HashSet};

fn main() {
    println!("{:.2}", circle::area(1.0));
    println!("{:.2}", square_area(3.0));

    let mut stock = BTreeMap::new();
    stock.insert("bolts", 40);
    let mut seen = HashSet::new();
    seen.insert("bolts");
    println!("{} {}", stock.len(), seen.len());
}

What reviewers expect

These are the conventions from the Rust book, and what a code review will push you toward:

  • Functions: import the parent module and call module::function(): use std::io; then io::stdin(). The call shows the function isn't local.
  • Types (structs, enums, traits): import the type itself: use std::collections::HashMap; then HashMap::new().
  • Two things with the same name: keep their modules (fmt::Result vs io::Result), or rename one with as.
  • Globs: avoid them in normal code, since readers can't tell where names come from. They're fine for preludes (use rayon::prelude::*;) and for use super::*; in test modules.
  • Group use lines at the top of the module; cargo fmt sorts them, and rust-analyzer can add them for you.

use is per module

A use only applies to the module it's written in. Modules inside it don't inherit it:

use std::collections::HashMap;

mod stats {
    pub fn count(words: &[&str]) -> HashMap<String, usize> {
        let mut counts = HashMap::new();
        for w in words {
            *counts.entry(w.to_string()).or_insert(0) += 1;
        }
        counts
    }
}

fn main() {
    println!("{}", stats::count(&["a", "b", "a"]).len());
}

error[E0425]: cannot find type `HashMap` in this scope

Move the use std::collections::HashMap; line inside mod stats, where the code that needs it is. (In the broken version, the compiler also warns that the root's use is unused: nothing at the root needs it.)
