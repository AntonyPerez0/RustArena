Destructuring, and returning several values

Writing .0 and .1 everywhere gets tiring, and it hides what the values mean. Destructuring unpacks a tuple into separate, well-named variables in one let:

fn main() {
    let point = (3, -7);
    let (x, y) = point;
    println!("x = {x}, y = {y}");
}

x = 3, y = -7

The left side, (x, y), is a pattern: it has the same shape as the value, and each name receives the part in its position. If you don't need a part, put _ in its place: let (x, _) = point; takes only the x.

Returning several values from a function

A function returns exactly one value, but that value can be a tuple. This is the everyday use of tuples: a function that works out two or three related results at once.

fn sum_and_average(a: f64, b: f64, c: f64) -> (f64, f64) {
    let sum = a + b + c;
    (sum, sum / 3.0)
}

fn main() {
    let (total, avg) = sum_and_average(4.0, 7.5, 9.5);
    println!("total {total:.1}, average {avg:.2}");
}

total 21.0, average 7.00
  • The return type (f64, f64) says "two floats". The parentheses are required: -> f64, f64 is a syntax error.
  • The last line of the body, (sum, sum / 3.0), builds the tuple. With no ; it's the function's return value, as you saw in the functions module.
  • The caller destructures the result straight away, so each value gets a meaningful name.

Two more things tuples explain:

  • The unit type () from the functions module is a tuple with zero values. A function with no -> returns it.
  • Swapping two values is one line: let (a, b) = (b, a); builds a tuple from the old values, then unpacks it into new (shadowing) variables.

Common mistakes

  • A pattern with the wrong shape. The pattern must have exactly as many names as the tuple has values:
fn main() {
    let (x, y) = (1, 2, 3);
    println!("{x} {y}");
}

error[E0308]: mismatched types

The full message says expected a tuple with 3 elements, found one with 2 elements. Use _ for a value you want to skip: let (x, y, _) = (1, 2, 3);

  • Getting the order wrong. let (avg, total) = sum_and_average(...) compiles fine (both are f64) but swaps the meanings. Tuple parts have no names, so the order is the only thing that tells them apart. Keep the order consistent and say it in a comment or the function's name.
