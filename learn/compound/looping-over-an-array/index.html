Looping over an array

Arrays shine when you combine them with loops: one piece of code that handles every element, however many there are. There are two ways to loop.

Loop over the elements

fn main() {
    let temps = [18, 21, 19, 25, 23];
    let mut sum = 0;
    for t in temps {
        sum += t;
    }
    println!("sum: {sum}");
    println!("average: {:.1}", sum as f64 / temps.len() as f64);
}

sum: 106
average: 21.2

for t in temps runs the body once per element, in order, with t set to each one. No index, so no way to go out of bounds. This is the pattern for totals, counts and searches. Note the average: both numbers are converted to f64 with as so the division keeps its fraction.

Loop over the indexes

When you need the position as well as the value, loop over the range 0..temps.len(), which is exactly the valid indexes (0, 1, 2, 3, 4):

fn main() {
    let temps = [18, 21, 19, 25, 23];
    let mut hottest = 0; // index of the hottest day so far
    for i in 0..temps.len() {
        if temps[i] > temps[hottest] {
            hottest = i;
        }
    }
    println!("hottest: day {} with {} degrees", hottest + 1, temps[hottest]);
}

hottest: day 4 with 25 degrees

Changing every element

In for t in temps, t is a copy of each element: changing t doesn't touch the array. To change the elements, use the index:

fn main() {
    let mut prices = [120, 75, 300];
    for i in 0..prices.len() {
        prices[i] = prices[i] * 110 / 100; // +10%, in whole cents
    }
    println!("{:?}", prices);
}

[132, 82, 330]

At work: Rust programmers write for x in array whenever they don't need the index. Clippy's needless_range_loop lint points out index loops that could be simpler, and suggests iterator methods (.iter(), .iter_mut(), .enumerate()) that you'll learn in modules 16 and 27. Until then, index loops are the right tool when you need the position or want to change elements.

Common mistakes

  • 0..=temps.len() goes one step too far: the last round asks for temps[5] and panics. Use 0..temps.len().
  • Starting a maximum at 0. If every value is negative (a cold week: -5, -2, -9), a "max" that starts at 0 never changes and reports 0, which isn't even in the array. Start from the first element instead: let mut max = temps[0];
  • Expecting for t in temps to change the array. It works on copies; use the index form.
