Testing failures: should_panic and Result

Code that rejects bad input is just as important to test as code that handles good input. Rust gives you two tools, matching the two ways code reports failure.

#[should_panic]: the code is supposed to panic

Some functions panic on misuse: indexing past the end, or a withdraw that refuses to overdraw. Add #[should_panic] under #[test], and the test passes only if the code panics. Add expected = "..." to also check the panic message contains that text, so the test doesn't pass by accident because of some other panic:

#[test]
#[should_panic(expected = "insufficient funds")]
fn spending_more_than_the_balance_panics() {
    let mut wallet = Wallet { balance: 10 };
    wallet.spend(25);
}

In the cargo test output, these tests are marked: test tests::spending_more_than_the_balance_panics - should panic ... ok.

Tests that return Result

Most Rust code reports errors with Result. You can check those with plain asserts (assert!(r.is_err()), assert_eq!(r, Ok(250))), and a test function may also return Result<(), E> itself. Then you can use ? inside it: if any step returns Err, the test fails with that error. It reads like normal code instead of a pile of .unwrap()s:

#[test]
fn parses_and_spends() -> Result<(), String> {
    let amount = parse_amount("250")?; // an Err here fails the test
    let mut wallet = Wallet { balance: 1000 };
    wallet.spend(amount);
    assert_eq!(wallet.balance, 750);
    Ok(())
}

The same checks work in a normal program, so here they are, running:

fn parse_amount(s: &str) -> Result<u64, String> {
    let n: u64 = s.trim().parse().map_err(|_| format!("not a number: {s:?}"))?;
    if n == 0 {
        return Err(String::from("amount must be positive"));
    }
    Ok(n)
}

fn main() {
    println!("{:?}", parse_amount("250"));
    println!("{:?}", parse_amount("0"));
    println!("{:?}", parse_amount("ten"));
    assert!(parse_amount("-3").is_err());
    assert!(matches!(parse_amount(" 7 "), Ok(7)));
    println!("checks passed");
}

matches!(value, pattern) (from the enums module) is handy in tests when you care about the shape of a value but not every detail, like "it's an Err of any kind".

Ignoring slow tests

#[ignore] under #[test] skips a test in a normal run (it shows as ignored). Run those with cargo test -- --ignored. Teams use it for tests that are slow or need a network.

Common mistakes

  • #[should_panic] without expected: the test passes on any panic, including an unrelated unwrap on None in your setup code.
  • Using #[should_panic] for functions that return Result: they don't panic on bad input, they return Err. Assert on the Result instead.
  • Forgetting Ok(()) at the end of a test that returns Result: error[E0308]: mismatched types.
