Drop and Deref

Drop: code that runs when a value goes away

In the ownership module you saw that a value is dropped at the end of its scope: its memory is freed. Drop lets you run your own code at that moment.

struct Connection {
    id: u32,
}

impl Drop for Connection {
    fn drop(&mut self) {
        println!("closing connection {}", self.id);
    }
}

fn main() {
    let _a = Connection { id: 1 };
    {
        let _b = Connection { id: 2 };
        println!("inner scope ends");
    }
    let c = Connection { id: 3 };
    drop(c);
    println!("main ends");
}

  • fn drop(&mut self) runs automatically. _b is dropped when the inner block ends; _a when main ends.
  • Values in the same scope are dropped in reverse order of creation (last in, first out), so things created later, which may depend on earlier ones, go away first.
  • drop(c) drops a value early. It's an ordinary function (std::mem::drop) that takes ownership and lets the value go out of scope.

This pattern is called RAII ("resource acquisition is initialization"): a value owns a resource and releases it in Drop, so you can't forget. Files close themselves, MutexGuards unlock their mutex, network connections hang up. You rarely write Drop for plain data; you write it for types that own something outside your program's memory.

Deref (briefly): * and automatic method calls

Deref lets a wrapper type act like a reference to what it contains. You use it all the time without noticing: a String derefs to str (that's why &String works where &str is expected) and a Vec<T> derefs to [T].

use std::ops::Deref;

struct Username(String);

impl Deref for Username {
    type Target = str;

    fn deref(&self) -> &str {
        &self.0
    }
}

fn greet(name: &str) -> String {
    format!("hi {name}")
}

fn main() {
    let u = Username(String::from("ferris"));
    println!("{} {}", u.len(), u.to_uppercase());
    println!("{}", greet(&u));
}

  • type Target = str; is what the wrapper derefs to, and deref returns a reference to it.
  • u.len(): Username has no len method, so Rust derefs and finds str::len.
  • greet(&u): a &Username turns into a &str automatically. This is deref coercion.

Use Deref for smart pointers and thin wrappers like this one. The smart pointers module comes back to Deref and Drop in depth.

Common mistakes

  • Calling .drop() yourself. c.drop() gives error[E0040]: explicit use of destructor method, because Rust would then run it a second time at the end of the scope. Call drop(c), which takes ownership.
  • Expecting creation order. Values in one scope are dropped last-created first, so the output of Drop impls can surprise you.
  • Copy and Drop together. error[E0184]: the trait `Copy` cannot be implemented for this type; the type has a destructor: with copies around, the cleanup would run several times.
  • Deref to fake inheritance. "My Admin derefs to User, so it gets all of User's methods" confuses readers, and the Rust API guidelines advise against it. Use a field and forward the methods you need, or a shared trait.
