FromStr: parse into your own type

"42".parse::<i32>() works because i32 implements the trait std::str::FromStr. Implement it for your own type and .parse() works for it too. This is the idiomatic way to turn text (config files, command-line arguments, user input) into a value.

use std::str::FromStr;

#[derive(Debug)]
struct Setting {
    key: String,
    value: i64,
}

impl FromStr for Setting {
    type Err = String;

    fn from_str(s: &str) -> Result<Self, Self::Err> {
        let (key, value) = s.split_once('=').ok_or(format!("missing '=' in {s:?}"))?;
        let key = key.trim();
        if key.is_empty() {
            return Err(String::from("empty key"));
        }
        let value = value.trim().parse::<i64>().map_err(|_| format!("bad number {value:?}"))?;
        Ok(Setting { key: key.to_string(), value })
    }
}

fn main() {
    let s: Setting = "volume = 7".parse().unwrap();
    println!("{} -> {}", s.key, s.value);
    println!("{:?}", "volume".parse::<Setting>());
    println!("{:?}", "=3".parse::<Setting>());
    println!("{:?}", "lives=lots".parse::<Setting>());
}

volume -> 7
Err("missing '=' in \"volume\"")
Err("empty key")
Err("bad number \"lots\"")

Piece by piece:

  • type Err = String; is the error type. It's spelled Err here (TryFrom uses Error): an old naming accident you just have to remember.
  • fn from_str(s: &str) -> Result<Self, Self::Err> does the parsing.
  • s.split_once('=') splits at the first = and returns Some((before, after)), or None if there's no =. .ok_or(...) turns that Option into a Result, and ? returns the error early.
  • .map_err(|_| ...) replaces the ParseIntError with a friendlier message. The |_| ... is a small inline function (a closure, a later module) that ignores the original error.
  • You don't call from_str yourself: write .parse::<Setting>(), or .parse() with the type annotated on the variable.

Why not a fn parse_setting(s: &str)?

It would work, but FromStr plugs into the rest of the ecosystem. Code that reads "any value that can be parsed" (T: FromStr) works with your type automatically: command-line parsers like clap, config loaders, and your own generic helpers.

Common mistakes

  • type Error instead of type Err gives error[E0437]: type `Error` is not a member of trait `FromStr` .
  • Forgetting use std::str::FromStr;. FromStr isn't in the prelude, so the impl line can't find it (or write impl std::str::FromStr for ...).
  • unwrap() on user input. It's fine in a quick example; in real code, handle the Err (with match or ?), because users will type lots.
